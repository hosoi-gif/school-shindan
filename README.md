# スクール診断（School Shindan）

## プロジェクト概要

ライフイズテック株式会社のIT・プログラミングキャンプ（対象：中高生）内で使う「スクール診断」ミニアクティビティ。キャンプ参加者にスクール事業（1年制プログラミングスクール）への入塾興味を持ってもらうための、MBTI風の遊び心ある診断コンテンツ。

## ゴール

キャンプの合間（5〜10分）に生徒がスマホ/PCで診断を受け、ふざけたノリの「診断タイプ」と、対応するスクールコースのおすすめ度が分かる → その場でスタッフが入塾窓口へ自然に接続する、という流れを作る。

## v5：Node.jsサーバー化（現行版）

v4までは「サーバーなし・単一HTMLファイルを手動配布」する仕組みだったが、v5から**Node.js + Express製のWebサーバー**に作り替えた（DBは使わずファイルに保存。もう一方のプロジェクト [MQP-quiz-system](../MQP-quiz%20system) と同じ考え方）。会場ごとに本物のURLを発行し、そのURLを配ることで参加者・会場担当スタッフがアクセスできる。

### 画面構成

1. **最上位管理画面**（`/admin`、パスワード保護）
   - スタート画面文言・質問（全会場共通）・コース（コース紹介文・熱血/クールタイプ・先輩作品ギャラリー含む）を編集
   - 「メンター紹介（そのほかのメンター）」：診断結果と同じタイプ（コース×熱血/クール）の時だけ結果画面に表示される、全会場共通のメンター一覧（名前・写真URL・一言紹介）を編集
   - 「この内容を保存する」でサーバーに保存
   - 「会場設定画面へ」ボタンで次の画面へ
2. **会場設定画面**（`/admin/venues`、パスワード保護）
   - 会場を追加すると、その会場専用の「設定URL」（`/v/:id/admin`）と「参加者URL」（`/v/:id`）が発行される
   - 発行された設定URLを会場担当スタッフに渡せば、最上位管理画面のパスワードを教えなくてもその会場の設定だけを任せられる
   - 会場の削除も可能
3. **会場オリジナル設定画面**（`/v/:会場ID/admin`、**パスワード不要＝URLを知っていることが鍵**）
   - その会場だけの「ボーナス質問」（診断のスコアに一切影響しない、笑える質問）を好きな数だけ追加。質問文・選択肢（自由な数）・挿入位置（0=最初の質問より前、N=共通のN問目の直後）を設定できる
   - その会場だけの「メンター」（この会場担当のスタッフなど）も同様に登録できる。診断結果と同じタイプの時だけ結果画面の「この会場のメンター」枠に表示される
   - 会場ごとに完全に独立したデータなので、ある会場を編集しても他の会場には一切影響しない
   - 参加者URL（`/v/:会場ID`）をここで確認・コピーできる
4. **診断ツール本体**（`/v/:会場ID`、生徒が開く画面）
   - 共通の質問・コースと、その会場のボーナス質問を合成して出題する
   - 結果画面には、診断結果と同じタイプのメンターが「この会場のメンター」「そのほかのメンター」の2枠に分けて表示される（一致するメンターがいない場合はその枠ごと非表示）

### 技術構成

- `server.js` … Expressサーバー本体。API（`/api/...`）とページ配信の両方を担当。
- `src/dataDir.js` … データ保存先ディレクトリ（`DATA_DIR`環境変数で上書き可。Railway Volume対応）。
- `src/configStore.js` … 全会場共通設定（`data/config.json`）の読み書き。
- `src/venueStore.js` … 会場一覧・各会場のボーナス質問（`data/venues.json`）の読み書き。ランダムな16進数8桁を会場IDとして発行。
- `src/defaultConfig.js` … 初回起動時に使われる初期設定（v4までの内容を引き継ぎ）。
- `public/` … 各画面のHTML/CSS/JS（ビルド不要、素のHTML+vanilla JS）。
  - `quiz.html` / `quiz-engine.js` … 診断ツール本体
  - `admin/index.html` / `admin/admin.js` / `admin/auth.js` … 最上位管理画面
  - `admin/venues.html` / `admin/venues.js` … 会場設定画面
  - `venue-admin.html` / `venue-admin.js` … 会場オリジナル設定画面
  - `shared.css` … 全画面共通のスタイル
- `legacy/` … v4までの「サーバーなし・単一HTMLファイル」版（`school_shindan.html`・`admin.html`）を参考用に保存。現在は使わない。

### 認証・権限モデル

- `/admin`・`/admin/venues`とそのAPI（設定の保存、会場の作成/削除など）は環境変数`ADMIN_PASSWORD`で保護（未設定時は`changeme`）。ヘッダー`x-admin-password`で照合する簡易的な方式で、ブラウザのsessionStorageにパスワードを保持する（タブを閉じると再入力が必要）。
- `/v/:venueId/admin`と`/v/:venueId`、およびそのAPIは**認証なし**。会場IDはランダムな8桁の16進数で推測困難なため、「そのURLを知っている＝そこにアクセスしてよい」というMQP-quiz-systemと同じ考え方（会場ごとの合言葉URL方式）。

### ローカルでの動かし方

```bash
cd "School_MBTI"
cp .env.example .env   # 初回のみ。ADMIN_PASSWORDなどを設定
npm install
npm run dev              # nodemonで起動。ファイル保存で自動再起動
# または npm start        # 通常起動
```

起動後、ブラウザで `http://localhost:3101/admin` を開く。

## スコアリングの仕組み

10問・6択（RIASEC＝ホランド理論の6興味タイプ R:現実的／I:研究的／A:芸術的／S:社会的／E:企業的／C:慣習的に対応）。管理画面での**保存データ上は**選択肢が必ずR→I→A→S→E→Cの順で並んでいるが、**参加者の画面ではその6つを毎回ランダムな順番で表示する**（常に同じ位置＝同じタイプという規則性を防ぐため）。表示順が変わってもクリック時にどのletterかは正しく判定されるので、スコアリング自体には影響しない。コース別スコアは「回答者のRIASEC得点 × コースの重み」の内積で算出し、最高スコアのコースがおすすめになる。フレーバー軸（熱血/クール）はE+S（対人・行動力）vs C+I（分析・秩序）の合計比較で決定。5コース×2フレーバー＝10種類の診断タイプ。

適性%グラフは、理論上の満点（重み×設問数）ではなく**その回答者の中で一番スコアが高かったコースを基準**に正規化している（`courseScore ÷ 最高スコア × 99%`、15〜99%でクリップ）。理論上の満点を基準にすると実際の回答ではほぼ届かず、おすすめのコースですら30〜40%程度にしかならず説得力に欠けたため、v5.2でこの方式に変更した。これにより、一番近いコースは常に90%台の高い数字で表示され、他のコースはそれとの相対差で決まる。

## 既知の未完成部分（次にやるべきこと）

2. QRコード・申込URLも同様に未設定（空欄）のまま。
3. 会場ごとのボーナス質問もまだ1件も作られていない（会場を作成し、会場オリジナル設定画面から質問を追加する必要がある）。

5. `ADMIN_PASSWORD`は簡易的な入室制限であり、強固なセキュリティではない。中身を見られて困る情報は入れないこと。

## 経緯・設計判断のメモ

- 当初は5タイプ（コース1つにつき1タイプ）で「まじめめ」なトーンで作ったが、ユーザーから「もっとふざけた感じにしたい」「10タイプくらい欲しい」という要望があり、「コース×フレーバー(熱血/クール)」構成に作り直した（v1）。
- 診断結果は単一のおすすめコースだけでなく、5コース全部の「適性%」を見せることで、MBTIのような"データっぽさ"を演出している。
- v1では「各設問の選択肢がそのままコースに1対1対応」という単純な多数決方式だった。ユーザーから「論理的に適性を決めたい」という要望があり、RIASEC（ホランド理論）を土台にした重み付き内積スコアリング方式に刷新した（v2）。
- v2まではコース・タイプ・ギャラリーの中身がHTML内のJSオブジェクトに直書きされており、変更にはコード編集が必要だった。「イベント前に内容を編集する管理画面が欲しい」「コースが増えたときに追加できるようにしたい」という要望があり、`admin.html`という編集画面から質問・コース・タイプ・ギャラリー・QRコードを編集し、完成したHTMLを書き出せる構成にした（v3）。
- v4：「診断とは全く関係ない、会場ごとに変えられる笑える質問を挟みたい」「会場の設定画面を作って、他の会場に影響しないようにしたい」という要望があり、会場ごとの独立した`bonusQuestions`（挿入位置つき）を追加。この時点ではまだサーバーなし・ファイル書き出し方式だった。
- v5：ユーザーから「会場ごとのURLを発行したい」という明確なイメージ（最上位管理画面／会場設定画面／会場オリジナル設定画面、という3階層）が示され、これは「ファイルを書き出して配る」方式では実現できない（URLはサーバーがあって初めて存在する）ため、Node.js + Express + ファイルベース保存のサーバーに全面的に作り替えた。技術構成・認証方式（最上位はパスワード、会場個別はURL知っていること自体が鍵）は、同じユーザーが運用しているMQP-quiz-systemの設計をそのまま踏襲している。v4までの単一HTMLファイル版は`legacy/`に保存し、参考用として残してある。GitHub（`hosoi-gif/school-shindan`）・Railway（Hobby Plan）への実デプロイもこのタイミングで完了した。
- v5.1：ユーザーから「同じタイプのメンターを紹介するコーナーが欲しい」という要望があり、コース×熱血/クールのタイプと紐づく「メンター」（名前・写真URL・一言紹介）を追加。全会場共通のメンター（最上位管理画面で編集）と、会場だけのメンター（会場オリジナル設定画面で編集）の2種類があり、結果画面では診断結果と同じタイプの人だけが「この会場のメンター」「そのほかのメンター」の2枠に分けて表示される（該当者がいない枠は非表示）。
- コース体系の実態確認：ユーザーから実際のスクールコース一覧（iPhoneアプリ／Unityゲーム／Webデザイン／Webサービス／映像制作の5コース）が共有され、それまで想定で入れていた「Androidアプリ」コースが実在しないことが判明。Androidアプリコースを削除し、代わりに映像制作コース（RIASEC重み A:2, R:1）を追加した。本番環境のデータも同様に修正済み。
- 質問の見直し：「中高生が問題数の多さで途中離脱するかも」という現場からの指摘があり、全12問→10問に削減。「休み時間の過ごし方」（放課後の質問と内容が重複）と「将来これならずっとできると思うのは」（最もキャリア色が強く堅い）の2問を削除し、残り全問の言い回しも「得意げに語れることと言えば？」「褒められて一番テンション上がるのは？」のように軽いトーンに書き換えた（選択肢が表すRIASECタイプ自体は変更していないため、スコアリングには影響しない）。スコア計算・適性%グラフは質問数を動的に読み取る作りなので、問題数を変えてもコード修正なしで正しく動作する。
- 質問の並び替え（ドラッグ&ドロップ）：最上位管理画面の質問カードは「⠿」部分をドラッグして順番を入れ替えられる。設問の並び順はスコア計算に影響しない（各設問内の6択とRIASECの対応は設問ごとに固定のため）。会場オリジナル設定画面のボーナス質問も、数字入力（挿入位置）ではなく、共通質問（グレー・編集不可）とボーナス質問を実際の出題順に並べた一覧の中で、ボーナス質問カードをドラッグして好きな位置に差し込む方式に変更した。共通質問の並びを変えた場合、既存のボーナス質問が挿入される「N問目の直後」の中身が変わる可能性がある点は要注意（挿入位置の数値自体は自動では変わらない）。
